# Рабочая интеграция отчётов

10.10.2026 владелец запросил подключение основной Google Таблицы.
Рабочая таблица: https://docs.google.com/spreadsheets/d/1vC8zXVTzKzvWPw_vOx7OKXEtJyx9zQJr-Y1Kbn-QLR4/edit
Резервная копия перед подключением: https://docs.google.com/spreadsheets/d/1lmYEy72SRvzfYBcnZnFpUBbsfRTQXR4jMDtQ2BorK9o/edit

Новые рабочие отчёты используют /ops_v3 и отдельную IndexedDB-очередь production.
Тестовая версия продолжает /ops_v3_test и прежнюю очередь: старые тестовые отчёты не попадут в рабочую таблицу.
Сервер разрешает production только после PRODUCTION_ENABLED=true и только с GitHub Pages origin.
Рабочие свойства PRODUCTION_SPREADSHEET_ID/PRODUCTION_PHOTO_FOLDER_ID отделены от тестовых.
Пароль ADMIN_PASSWORD сохраняется без чтения или переноса в исходники. MODE=test сохраняет доступ старой тестовой версии.
В админке закреплена ссылка на рабочую Google Таблицу.
Клиенты, QR-коды и штампы не изменяются. Ни один синтетический финансовый отчёт не отправляется в рабочую таблицу для проверки.

## Проверка и подключение

10 октября 2026 выполнена живая проверка из аккаунта владельца: для каждой точки
созданы синтетические поставка, дневной чек-лист и закрытие смены. В Drive сохранены
фото накладной, чек-листа, закрытия и выручки. Все шесть отчётов получили `synced`;
каждый повторён с тем же ID. Это проверка серверной записи, а не мобильного интерфейса
или публичного endpoint. Предыдущий пробный запуск для точки 1 также остаётся в копии.

После согласованного развертывания endpoint проверен реальными HTTP POST:
отклоняет отчёт без личного пароля, изменение шаблона без административного пароля
и запрос `mode=production`. Возвращает HTML с каналом подтверждения и nonce.
Положительная отправка через iframe и мобильную камеру остаётся отдельной проверкой.

`runEndpointIntegrationTest` проверяет действующий TEST endpoint реальными POST:
отправку фото, повтор ID, добавление, редактирование и архивирование пункта для обеих
точек, затем восстанавливает исходный шаблон. Пароли используются только внутри
скрипта и не выводятся в результаты. Проверка прошла после настройки владельцем
`ADMIN_PASSWORD`; фотографии/строки сохранены только в копии. 14 автоматических тестов
проверяют в том числе требование положительного серверного подтверждения входа админа.

1. `node --test tests/operations.test.cjs` — тесты UI-разметки, очереди, ошибок,
   шаблонов, обязательных фото, изоляции сотрудников, идемпотентности и сумм.
   Это имитация сервисов, а не подтверждение живой интеграции.
2. В отдельном Apps Script выполните `runIntegrationSmokeTest`. Google потребует
   разрешения на таблицы, Drive и внешние запросы. Функция создаёт только синтетические
   тестовые поставку, чек-лист и закрытие смены для обеих точек в копии/тестовом пространстве,
   затем повторяет их с теми же ID для проверки дублей. Гостей она не читает/не меняет.
3. Проверьте строки и фото, повторную отправку и доступ к снимкам в Google Drive.
4. Добавьте в Script Properties `ADMIN_PASSWORD` (действующий пароль администратора,
   вводится владельцем без передачи в чат). Остальные свойства выставляет тест:
   `MODE=test`, `SPREADSHEET_ID`, `PHOTO_FOLDER_ID`.
5. После проверки создайте отдельное web app deployment от владельца. Доступ
   endpoint требует явного согласования; отчёты защищаются серверной проверкой
   сотрудника, а настройки — `ADMIN_PASSWORD`. Секреты и OAuth-токены в GitHub не добавлять.
6. В `operations-v3.js` указан отдельный тестовый deployment в `REPORTS_WEBHOOK_URL`.
   `OPS_V3_TEST_MODE=true`: копия таблицы и `/ops_v3_test`. Серверная запись проверена,
   но отправка через реальный мобильный интерфейс/iframe ещё не подтверждена.
7. Проверьте мобильную камеру, качество текста накладной, восстановление фото после
   перезапуска, медленную сеть, iframe-подтверждения на реальном GitHub Pages origin.

## Перед рабочим запуском

Нужны проверка живого endpoint, Firebase rules, доступов и качества снимков. В старом
приложении личные пароли сотрудников используются существующей Firebase-схемой.
Новая проверка админа защищает новый приёмник и редактор чек-листов; прямые старые
Firebase-операции требуют проверки rules. Это не замена полноценной серверной авторизации.
Новые расширенные доступы и смена паролей не выполняются автоматически.

Переключение в production выполняется отдельно, только после успешной проверки и
согласования запуска: рабочий spreadsheet ID, закрытая рабочая папка, `MODE=production`,
`OPS_V3_TEST_MODE=false`, рабочий endpoint. `runIntegrationSmokeTest` всегда возвращает
настройки в тестовый режим: в рабочем проекте его не запускают. Тестовую и рабочую
интеграции держать отдельными проектами/deployment. Merge в main публикует GitHub Pages.
